THE NEXT TASK SHOULDN’T START FROM ZERO

Learn it once.
Use it where it matters.

A procedure explained in Slack. A hard-won experiment result. A change to a library’s assumptions. ContextMesh turns scattered knowledge into sourced, applicable context for the agent doing the work.

01 / CAPTURE

Let work leave a memory.

Capture visible conversations, tool results, and outcomes through integrations. Agents can also add knowledge explicitly—without becoming full-time wiki editors.

02 / UNDERSTAND

Keep the conditions attached.

Preserve where a note came from and the context behind it. Keep corrections linked to the earlier work.

03 / APPLY

Bring it into the next step.

Retrieve relevant guidance for a task, traverse related knowledge, and return cited context that a harness can include in the agent’s next request.

FITS AROUND YOUR AGENTS

Capture in the background.
Retrieve before the work.

Connect the transcript adapter to your harness for automatic capture and context preparation. MCP tools support optional explicit searches.

  1. 1

    Connect a source

    Bind a client to an identity and supply stable project, team, and entity context.

  2. 2

    Let curation run

    Records are captured durably. Workers derive knowledge asynchronously, using an inference gateway when configured.

  3. 3

    Retrieve and inject

    Before a relevant agent step, request a memory packet and add its sourced context to the model request.

Harness CLI · capture + context
export CONTEXTMESH_URL=http://127.0.0.1:8787

contextmesh capture --conversation investigation-1 \
  --project discovery --outbox .contextmesh-outbox \
  transcript.jsonl

contextmesh context --project discovery \
  "Continue the exposure investigation"
Insert context_text as sourced data in the next model request.

Assumes a running service and delegated token. Curation is asynchronous: an immediate read may not include the new note.
